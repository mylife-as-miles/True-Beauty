# Independent security/privacy review — round07

Reviewed 2026-11-02 against the new native Worker entry, operator/session authentication, encrypted D1 store, root Drizzle migrations and reasoning/YouCam/merchant routes. **No demonstrated high or critical defect remains within this bounded local review.** The former anonymous-spending defect is closed in the tested Worker path. Hosted platform behavior and genuine provider operations remain separate verification gates.

## Independent executed evidence

New suite: `tests/worker-boundary-r07.test.ts`. All requests enter the actual `handleHostedRequest()` function. `tests/helpers/edge-d1.ts` executes the real root SQL migrations, reservation trigger and transactional batches through Node's SQLite engine. Provider fetches are globally intercepted with explicitly scripted responses and fake credential strings. Unexpected fetch destinations throw inside the fixture; no external request is performed.

`npx vitest run tests/worker-boundary-r07.test.ts`: **22/22 passed** after reviewing the final discovery and owner-email changes. The suite includes 21 independently authored cases and one root-supplied first-visit discovery regression, inspected during this follow-up. Scoped ESLint passed after Prettier formatting. `npm run typecheck` passed again after the follow-up test edits; root also reports full lint/typecheck passing on the final source. These counts do not include the earlier Fastify review or the implementation agents' other fixture tests.

The suite demonstrates:

- The database has no initial budget row. Paid quoting fails before explicit operator reconciliation. A service bearer can initialize the cumulative ledger with at least **51 credits and 111000 micro-USD** already used, within total **100-credit / 5000000-micro-USD** limits. After a reservation, a reset to the initial amount returns 409 and preserves both totals; zeroed historical expenditure is rejected.
- Anonymous sessions cannot inspect/initialize the operator budget, list/approve/revoke requests, or reserve paid work. Supplying the configured operator ID/email in caller-controlled `oai-authenticated-*` headers does not establish operator identity when `SITES_IDENTITY_TRUSTED` is absent, `false` or `TRUE`. With an explicit `true` fixture configuration, only an exact owner ID or normalized allowlisted owner email accompanied by a nonempty dispatch ID is accepted. Missing/empty IDs, suffix-confused IDs/emails and unrelated emails fail. Status responses do not expose the allowlisted email or ID. The server-tooling bearer works independently; a modified bearer fails.
- Canonical HTTPS URL and exact Origin checks reject foreign/null/lookalike origins and another Worker alias, including requests carrying a valid service bearer. Signed-cookie payload/signature tampering, forged cookies, cross-origin cookie reuse, expired cookies and mismatched CSRF tokens cannot establish private ownership or mutation access. Operator mutations also require the signed session and CSRF capability. Read-only capability/source discovery may replace an invalid cookie with a fresh signed anonymous session; tests verify that this replacement does not inherit the old/attacker-selected owner or access the old owner's approved quote. Discovery does not initialize a budget or make a provider call.
- Asking for access does not grant access. An operator approval applies to one exact quote and its original session. A second quote, changed private payload and another session remain unauthorized. The operator pending list contains operation/cost/expiry metadata and does not expose the private goal/context.
- Ten concurrent starts consume one quote, create one encrypted reasoning record and reserve once. Two approved quotes racing for the final USD allowance admit one request and leave no extra task/reservation artifact. Two approved image tasks racing for the last credit allowance upload/create only once. These tests execute the actual SQLite trigger and batch rollback, rather than substituting an in-memory authorization store.
- Revoking a started quote prevents its next paid reasoning continuation and retains the conservative reservation. Another session cannot run or cancel its reasoning task. Concurrent Worker entries claim one durable turn; deleting its record while the scripted provider is pending prevents late output from returning a tool plan or recreating the task. Cancellation does not promise an upstream refund or cessation of already dispatched provider work.
- Declared and actual oversized JSON, oversized media requests and unsupported content types fail before quote creation/provider work. Successful scripted image submission leaves no source base64, fake provider credential or plaintext upstream task ID in stored rows.
- Private reasoning text and bounded responses are encrypted in D1; finished transcript content is cleared. Corrupted ciphertext fails authentication and produces a safe static error. Arbitrary upstream error bodies and exact credential reflection do not reach the Worker client. Missing data-encryption configuration fails before a quote can be persisted.
- Expired task access is denied. Subsequent activity prunes expired records while preserving cumulative usage. This verifies access expiry/activity pruning, not physical deletion at a particular wall-clock instant.

No real credential/environment values were inspected. No paid operation, genuine provider response, private-image upload, R2 write, native Site mutation or deployment was performed by this review.

## Security conclusion and evidence limits

The R07 Worker now distinguishes an anonymous session's CSRF/ownership capability from permission to spend the operator's money. Its approval and reservation boundary is exercised above using the actual route entry, encrypted store and SQL. The pass supports the implemented source path; it does not establish that the public Site is serving this exact build, that bindings/migrations are installed correctly, or that platform-dispatched identity headers cannot be forged.

Keep `SITES_IDENTITY_TRUSTED` false until the platform's stripping/replacement of caller identity headers and direct-alias behavior have been verified. Local tests of the explicit `true` configuration verify allowlist logic only; they cannot prove the platform provenance of those headers. The service-operator token must remain in native server tooling/runtime secrets and must not be distributed to a browser. No browser code or hosting configuration was changed during this review.

Node SQLite proves the executed SQL transaction/trigger behavior here. It is not a substitute for the integrating engineer's actual workerd/D1 or hosted multi-isolate proof. Genuine provider billing, live-output safety, provider retention/deletion enforcement and deployment secret handling were not evaluated with these scripted responses. Source images remain request memory in the reviewed routes; encrypted temporary task text/results have a 15-minute access lifetime and pruning on later activity. Scheduled physical cleanup remains unverified and must not be claimed as an exact deletion SLA.

**Verdict: all 22 boundary cases pass after the final source review; no reproduced high/critical source defect. Hosted platform identity/binding/build verification and separately authorized genuine provider checks remain necessary before a production security claim.**
